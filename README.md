# Uzum · дашборд карточек (1701 Store)

Интерактивный дашборд состояния товарных карточек на Uzum Market: динамика продаж,
ранг, остатки, воронка и готовые сигналы к действию по каждой карточке.

**Открыть:** https://ckimework-commits.github.io/uzum-1701-dashboard/

Страница самодостаточная — внешних запросов не делает, данные вшиты внутрь.
`index.html` можно скачать и открыть локально двойным кликом.

Второй магазин того же проекта — UytMarket (112728) — живёт в отдельном контуре:
свой аккаунт продавца, свой токен, свой дашборд
[uzum-portfolio-dashboard](https://ckimework-commits.github.io/uzum-portfolio-dashboard/).
Магазины не смешиваются ни в одном отчёте.

## Что внутри

| Файл | Что это |
|---|---|
| `index.html` | дашборд на дату последнего прогона (данные вшиты) |
| `data/portfolio_log.csv` | append-only лог снимков каталога: строка на (дата × карточка) |
| `data/sales_daily.csv` | продажи по дням: штуки, выручка, прибыль, заказы, отмены |
| `data/keys_manual.csv` | позиции по поисковым ключам — заполняется вручную |
| `data/changes.csv` | журнал правок карточек — заполняется вручную, эффект считается сам |

## Что показывает

- **Что делать** — воронка портфеля (просмотры → заказы → конверсия против медианы) и
  очередь задач, отсортированная по «призу»: сколько выручки в неделю лежит на столе,
  если довести карточку до медианы портфеля при её текущем трафике.
- **Карточки** — таблица с рангом, динамикой, призом и сигналом по каждой.
- **Правки и эффект** — что меняли в карточках и что из этого вышло на 7/14/30 день.

История коммитов = архив ежедневных снимков: любой день восстанавливается из git.

## Как обновляется

Локальный launchd-агент `com.uzum.monitor.1701store` ежедневно в **07:20 KST**:

1. `uzum_portfolio.py` — тянет Uzum Seller API (каталог + финансы), пишет CSV и xlsx;
2. `build_dashboard_html.py` — пересобирает `index.html` из CSV;
3. `deploy_dashboard.sh` — коммитит и пушит сюда (пустой diff → коммита нет).

Источник скриптов: локальный скилл `uzum-card-monitor`. Токен продавца живёт только
в `~/.config/uzum/`, в репозиторий не попадает.

## Границы данных

- Метрики каталога (ранг, просмотры, конверсия, % возвратов) — **скользящие**
  показатели API, поэтому фиксируются с датой снимка.
- Выручка и прибыль считаются **без отменённых** заказов;
  прибыль = выручка − комиссия − логистический сбор (из `/v1/finance/orders`).
- Позиции по поисковым ключам **не автоматизируются** (витрина Uzum закрыта капчей,
  у ZoomSelling нет API) — это ручной еженедельный срез в `data/keys_manual.csv`.
- История магазина начинается 29.07.2026 (первый снимок каталога); товар встал на
  склад Uzum 31.07.2026 — до этой даты остатки нулевые, и метрики воронки по ним
  сравнивать не с чем.
